# Регистрация и авторизация на backend

## Цель

Создать HTTP API на Go для регистрации и входа по логину и паролю. После успешной авторизации клиент получает JWT access-токен и refresh-токен; refresh-токен позволяет получить новую пару токенов. Восстановление пароля в эту задачу не входит.

## Реализация

- Добавить Docker Compose для PostgreSQL с постоянным томом для данных, настройками подключения через переменные окружения и проверкой готовности базы. Документировать запуск базы и backend.
- Использовать **GORM** и драйвер `gorm.io/driver/postgres` для работы с пользователями и refresh-сессиями. Добавить версионируемые SQL-миграции, применяемые отдельной командой, и документировать их запуск. GORM поддерживает PostgreSQL через pgx и предоставляет транзакции для безопасной ротации токенов ([подключение PostgreSQL](https://gorm.io/docs/connecting_to_the_database.html), [транзакции GORM](https://gorm.io/docs/transactions.html)).
- Хранить только хеши паролей и refresh-токенов.
- Добавить JSON API:
  - `POST /auth/register` — регистрация по уникальному логину и паролю с выдачей пары токенов.
  - `POST /auth/login` — проверка учётных данных и выдача пары токенов.
  - `POST /auth/refresh` — обмен действующего refresh-токена на новую пару.
- При обновлении атомарно отзывать использованный refresh-токен и создавать новый в транзакции, чтобы повторное или одновременное использование старого токена не выдавало дополнительные пары.
- Добавить проверку JWT для защищённых обработчиков: подписи, срока действия и идентификатора пользователя. Секрет подписи и параметры подключения к БД передавать через конфигурацию окружения.
- Возвращать понятные HTTP-статусы для некорректных данных, занятого логина, неверных учётных данных и недействительного либо истёкшего refresh-токена. Не раскрывать пароль или токены в логах.

## Проверка

- Покрыть тестами регистрацию, уникальность логина, вход с правильным и неправильным паролем, проверку JWT и обновление токенов.
- Проверить истёкший, неверный и повторно использованный refresh-токен, а также конкурентные запросы на обновление.
- Запустить PostgreSQL через Docker Compose, проверить миграции и сохранение данных после перезапуска контейнера. Выполнить `go test ./...` и `go build ./...` из `backend/`.

## Принятые значения

- PostgreSQL работает в Docker; backend для локальной разработки запускается отдельно.
- Access JWT действует 15 минут, refresh-токен — 30 дней; сроки задаются конфигурацией.
- Refresh-токен передаётся в JSON-теле запроса и ответа. Каждое обновление продлевает сессию выдачей нового refresh-токена.
- Подтверждение логина, выход из сессии и восстановление пароля в текущий объём не входят.
